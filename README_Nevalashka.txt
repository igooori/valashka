3. Настройка окружения и запуск
Установить Python 3.11+.​

Создать виртуальное окружение в корне проекта:

python -m venv venv

Windows: venv\Scripts\activate

Linux/macOS: source venv/bin/activate

Установить зависимости:

pip install -r requirements.txt

Создать файл .env (или заполнить settings.py) с параметрами:

BOT_TOKEN — токен Telegram‑бота от BotFather.​

ADMIN_ID — Telegram ID администратора (или несколько через запятую).

Реквизиты ЮKassa (см. раздел ниже).

Запустить бота:

python main.py

При успешном старте в консоли будет сообщение вроде «бот запущен».

4. ЮKassa
Сейчас бот настроен на тестовый режим ЮKassa: реальные деньги не списываются, используются тестовые ключи.​

Чтобы включить боевой приём оплат:

Войти в личный кабинет ЮKassa и закончить подключение магазина (договор, проверки).​

Получить боевые реквизиты:

shop_id (идентификатор магазина)

secret_key (секретный ключ)

Передать эти значения разработчику или самостоятельно заменить их в настройках бота (файл settings.py или .env — по текущей реализации проекта).

Провести 1–2 тестовых реальных платежа на небольшую сумму и убедиться, что:

оплата проходит в ЮKassa;

бот выдаёт доступ («Путь»/«Сила»);

запись появляется в листе Payments Google Sheets.​

Логику бота менять не нужно — достаточно подставить боевые ключи.

5. Google Sheets (CRM)
Бот использует один общий файл в Google Sheets (NEVALASHKA_bot_CRM) с несколькими листами:

Users

user_id | registration_date | subscription_end

Содержит пользователей и срок окончания их подписки на «Путь».

Payments

user_id | payment_id | amount_rub | amount_usdt | currency | system | status | product_type | tariff_period | created_at | subscription_end | type

Фиксируются все оплаты (ЮKassa + крипта).

Applications

user_id | q1 | q2 | q3 | q4 | username | created_at | status

Анкеты уровня «Сила» и статус модерации.

Tickets

ticket_id | user_id | username | status | created_at | message | type

Обращения в поддержку.

Все записи в эти листы делает бот автоматически.

6. Логика уровней «Путь» и «Сила»
Уровень «Путь»
Пользователь выбирает тариф и оплачивает доступ (ЮKassa или крипта).​

После успешной оплаты:

в БД и Google Sheets фиксируется оплата и новая дата subscription_end;

пользователю приходит сообщение:
«Вы приняты. Доступ к уровню Путь открыт. Добро пожаловать в круг.»

появляется кнопка [Перейти в Путь] (ссылка на закрытый канал/чат уровня «Путь») и кнопка [Поддержка].

Уровень «Сила»
Пользователь оплачивает доступ к «Силе» и заполняет анкету (4 вопроса).​

Анкета попадает в лист Applications со статусом «на модерации».

7. Поддержка (тикеты)
При нажатии кнопки «Поддержка» бот просит пользователя описать проблему.​

Следующее текстовое сообщение:

создаёт/обновляет тикет в БД;

отправляется админу в личку (в Telegram);

записывается строкой в Tickets в Google Sheets.

Администратор отвечает пользователю напрямую в ЛС из своего аккаунта.

8. Что можно менять без доработки кода
Тексты сообщений бота — в файлах commands.py, payments.py, applications.py, support.py.

Ссылки на каналы/чаты «Путь» и «Сила» — в функциях выдачи доступа (поиск по коду по словам Перейти в Путь и Перейти в Силу).​

Тарифы и период подписки — задаются в логике формирования тарифов (раздел с кнопками выбора тарифа в payments.py); сами значения можно править в коде без изменения структуры БД и Sheets.​
